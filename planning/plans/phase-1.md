# Phase 1 — Foundation

Status: Done (Ahsan pushes)

## Goal

An empty but working skeleton connected to GitHub: a pnpm monorepo where `pnpm dev` runs a static-export
Next.js placeholder on `:3000` and a Hono Worker on `:8787` with `GET /health`, both able to use types
from `packages/shared`.

No business logic in this phase: no database, LLM, Redis, CORS, or chat endpoint.

## Tasks

1. **Git and workspace root.** `git init` on branch `main` and add the GitHub repo as remote `origin`. Add `pnpm-workspace.yaml` (`apps/*`,
   `packages/*`, `scripts`), root `package.json` (`engines.node >=22`, pinned `packageManager`),
   `.gitignore`, `.prettierrc`, `tsconfig.base.json` (strict). Allow only the native build scripts the
   stack needs (`esbuild`, `workerd`, `sharp`), since pnpm blocks them by default.
2. **`packages/shared`** (`@storeassist/shared`). Zod schemas and inferred types, exported as TypeScript
   source with no build step:
   - `SourceSchema`: `{ title, slug, excerpt }`
   - `ChatRequestSchema`: `{ messages: [{ role: "user" | "assistant", content }] }`, with limits of
     1–6 messages and 1–500 characters each
   - `ChatResponseSchema`: `{ answer, sources: Source[], isFallback }`
   - `HealthResponse` type and a `STORE_NAME` constant, which give the two apps something real to import
   - These shapes are provisional. `plans/phase-4.md` holds the final API spec and may change them.
3. **`apps/api`**. Hono on Workers:
   - `wrangler.jsonc`: name `storeassist-api`, entry `src/index.ts`, dev port 8787
   - `src/index.ts` mounts `src/routes/health.ts`; `GET /health` returns exactly `{"ok":true}`, typed
     with `HealthResponse`
   - `.dev.vars.example` lists the 7 fixed env var names with empty values (`ALLOWED_ORIGIN` defaults
     to `http://localhost:3000`)
   - `build` script runs `wrangler deploy --dry-run --outdir dist`, which bundles without deploying
4. **`apps/web`**. Next.js App Router, TypeScript, Tailwind:
   - `output: "export"` and `transpilePackages: ["@storeassist/shared"]`
   - One placeholder page showing `STORE_NAME`, "StoreAssist AI", and "Demo with fictional sample data.
     Not a real store."
5. **`scripts`**. A private workspace package with `package.json` and `tsconfig.json` only. Real scripts
   arrive in Phase 3.
6. **Quality tooling.** Root `eslint.config.mjs` (typescript-eslint, `no-explicit-any` as an error,
   Next rules for `apps/web`) and Prettier.
7. **Root scripts.** `pnpm dev` (both apps in parallel), `pnpm build`, `pnpm lint`, `pnpm typecheck`,
   `pnpm format`.
8. **Verify and gate.** Run the checks below and show the results. Stop for Ahsan's "approved".
9. **After "approved".** Update `STATUS.md`, `SETUP.md`, and the `CLAUDE.md` commands table. Make one
   commit (`chore: scaffold monorepo foundation`) and tag `phase-1` locally. **Claude does not push.**
   Ahsan pushes with `git push -u origin main; git push origin phase-1`.

**Version pins:** latest stable at install, locked by `pnpm-lock.yaml`, except TypeScript at `~5.9.3`.
TypeScript 7 is out, but typescript-eslint accepts only `<6.1.0`.

## Risks / open questions

**Process note**

- `PLAN.md` puts "code is on GitHub" in the gate, while `CLAUDE.md` commits docs with the code after the
  gate and allows one commit per phase. This plan keeps one commit: Ahsan approves the local result,
  Claude commits and tags locally, and Ahsan pushes.
- Private details (prices, profile notes, Neon project ID) were removed from `planning/` before the
  first commit, because the repo is public.

**Technical risks**

- ESLint 10 is new, and `eslint-config-next` plugins may not fully support it yet. If lint crashes, pin
  ESLint 9, which every tool here accepts.
- `@neondatabase/serverless` and the other runtime dependencies are not installed until the phases that use them.
- `wrangler dev` runs without keys in this phase because `/health` reads no env vars, so the `.dev.vars`
  copy is not a blocker for the gate.
